## ⭐ KEY DESIGN DECISIONS (INTERVIEW GOLD)

### Why Redux?

* Sidebar state used across multiple components
* Search caching for performance
* Avoids prop drilling

### Why Context API?

* Theme is UI-only global state
* No complex logic or middleware required

### Why Debouncing + Caching?

* Reduces API calls
* Improves user experience
* Demonstrates performance awareness

## ❓ INTERVIEW QUESTIONS & ANSWERS (VERY IMPORTANT)

### Q1. Why did you use Redux in this project?

**Answer:**
Redux is used to manage global UI state such as sidebar visibility and cached search results. These states are shared across multiple components, and Redux helps avoid prop drilling while keeping state updates predictable.

---

### Q2. Why not use Redux for theme management?

**Answer:**
Theme is UI-only state with simple logic. Using Redux would add unnecessary complexity. Context API is lightweight and more suitable for this use case.

---

### Q3. How did you optimize search functionality?

**Answer:**
I implemented debouncing using `setTimeout` to delay API calls until the user stops typing, and I cached search results in Redux to avoid repeated API requests for the same query.

---

### Q4. What is debouncing?

**Answer:**
Debouncing delays function execution until a certain amount of time has passed since the last event. In this project, it prevents frequent API calls while typing in the search bar.

---

### Q5. How does routing work in your app?

**Answer:**
I used React Router v6 with nested routing. The Body component acts as a shared layout containing the header and sidebar, while different pages are rendered inside an `Outlet`.

---

### Q6. What happens when a user clicks a video?

**Answer:**
The app navigates to `/watch?v=videoId`. The WatchPage reads the video ID from the URL, closes the sidebar using Redux, and embeds the YouTube iframe for playback.

---

### Q7. How is the app scalable?

**Answer:**
The app uses modular components, Redux slices for global state, reusable UI components like VideoCard, and clean routing. New features can be added without breaking existing logic.

---

### Q8. How do you prevent unnecessary re-renders?

**Answer:**
By separating container components from presentational components, using Redux selectively, and keeping UI-only state local or in Context.

---

### Q9. What challenges did you face?

**Answer:**
Managing global UI state and optimizing API performance. I solved this by introducing Redux for shared state and implementing debouncing and caching.
